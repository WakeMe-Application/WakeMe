# 깨워줘 iOS 앱 — Phase 1 MVP

![깨워줘 — 지하철 하차 알림](../brand/wordmark.png)

기획서 13장 구조를 따른다. 판정 엔진은 `../Engine`(Swift Package, Foundation만 의존)에 있고, 앱은 UI·시스템 연동만 담당한다.

```
App/
  project.yml              xcodegen 원본 (WakeMe.xcodeproj는 생성물)
  WakeMe/                앱 타깃
    App/                   진입점, AppModel(루트 상태 · 디버그 상태 주입)
    DesignSystem/          팔레트·버튼·노선 타임라인
    Features/              Home · StationPicker · TripSetup · Trip · Settings · Onboarding
    Services/              TripSession · 알림 예약 · Live Activity · 백그라운드 유지 · 저장소
  WakeMeWidgets/         Live Activity (잠금화면 · 다이내믹 아일랜드)
  Shared/                  앱·위젯 공용 (Activity 속성, 전광판 팔레트, 노선 배지)
Engine/
  Sources/WakeMeEngine/  노선 데이터 · 경로 계산 · 알림 시점 · 위치 추적기
  Tests/                   Swift Testing (macOS에서 `swift test`)
```

## 실행

```bash
cd App && xcodegen generate      # 파일을 추가·삭제했을 때
open WakeMe.xcodeproj          # Signing에서 Team 선택, Bundle ID 변경 후 Run
cd ../Engine && swift test       # 엔진 테스트
```

- 최소 iOS 26. Live Activity는 실제 기기와 시뮬레이터 모두에서 동작한다.
- 무료 Apple ID로도 설치된다. 알림을 방해금지 모드에서도 받으려면 유료 계정에서 **Time Sensitive Notifications** capability를 추가한다.

## 화면 톤

모든 화면이 탑승 전광판과 같은 다크 톤(`#090D16`)을 쓴다. 원본 값은 `BoardPalette`이고 `DS.background`·`DS.surface`가 그것을 가져다 쓴다. 앱은 Info.plist의 `UIUserInterfaceStyle: Dark`로 다크에 고정돼 있는데, 배경만 어둡게 하면 `.primary`·`.secondary` 같은 시스템 의미색과 세그먼트·토글·키보드가 라이트 기준으로 남아 글씨가 사라지기 때문이다.

홈 상단에는 앱 아이콘과 같은 브랜드 타일이 붙는다(`WakeMeWordmark`). 심볼 자체(`WakeMeMark`)는 위젯도 쓸 수 있도록 `Shared/`에 있고 코드로 그린다 — 원본은 `../tools/build_logo.swift`와 같은 기하다.

## 현재 한계 (다음 단계)

- **위치 판정은 시간 모델 + 가속도계 정차 감지 + 사용자 보정**이다. 앵커(출발 시각) 하나로 남은 시간을 계산하고, 가속도계가 정차를 감지하면 앵커를 다시 맞춘다. 예상 시각과 가까운 역을 고르고, 직전 역을 떠난 지 얼마 안 된 정차(터널 신호대기)는 무시한다. 설정에서 끄면 출발 버튼과 노선도 탭 보정만 쓴다.
- **자동 감지는 실제 지하철에서 검증하지 않았다.** 임계값(조용함 0.25 m/s², 정차 판정 8초, 이동평균 3초)은 추정치다. PoC 로거로 탑승 로그를 모아 `cd Engine && swift run ride-replay <ride.jsonl> --sweep`으로 실제 `StopDetector`에 재생하면, 액션 버튼으로 찍은 정답 마크와 대조해 놓침·오검출·오차를 채점하고 파라미터 조합을 비교해 준다. 시뮬레이터에는 가속도계가 없어 단위 테스트로만 검증했다.
- 노선 데이터는 **수도권 41개 운행 계통 1,134개 역**(1~9호선, 경의중앙, 수인분당, 신분당, 공항철도, 경춘, 경강, 서해, GTX-A, 인천 1·2호선, 김포골드라인, 신림선, 우이신설, 에버라인, 의정부경전철 + 지선 + 급행 9계통)이다. `../tools/build_network.py`가 공공데이터에서 생성한다.
- **역간 소요시간은 서울교통공사 1~8호선 구간만 실측**이다(2·5·6호선은 거의 전 구간). 코레일·타기관 구간과 9호선 이후 노선은 추정치(주행 95초 + 정차 30초)다.
- **급행 9계통**: 9호선 급행, 1호선 경인·경원·경부급행, 경의중앙선 경의선·중앙선·서울역급행, 수인분당선 분당선·수인선급행. 정차역은 위키백과 노선 문서에서 옮겼고, 구간 시간은 통과 구간의 합에 속도 계수(9호선 0.75, 코레일 0.9)를 곱한 **추정치**다. 실측과 비교하면 경인급행 9분 단축(알려진 값 약 11분), 9호선 25분 단축(약 20분) 수준이다.
- **실시간 열차위치 보정**은 기본 인증키가 앱에 내장돼 있어 설정 없이 바로 켜진다(`BuiltInKeys.realtimeSubway`, 설정에서 본인 키를 넣으면 그 키가 우선한다). 30초마다 노선 전체 열차 위치를 받아 출발역에 서 있는 열차를 탑승 열차로 잡고, 그 열차가 경로상의 역에 "도착"으로 보고하면 위치를 맞춘다. 역을 특정할 수 있어 가속도계보다 정확하다. API가 HTTP만 제공해 Info.plist에 ATS 예외를 뒀다.
- **내장 키는 소스와 앱 바이너리에 그대로 들어간다.** 저장소를 공개하거나 앱을 배포하기 전에 키를 새로 발급받아 갈아 끼우거나, 서버를 두고 프록시해 클라이언트에서 키를 빼야 한다.
- 탑승 화면에는 API가 알려 준 **열차의 실제 위치**를 상시 표시한다(예: "강남 진입 · 2054번 열차 · 방금"). 우리가 시간으로 추정한 "이번 역"과 다를 수 있는데, 그 차이를 숨기지 않아야 사용자가 화면을 얼마나 믿을지 판단할 수 있다. 실시간을 주지 않는 노선에서는 이 줄이 아예 나오지 않는다.
- **지원 노선**(2026-09 확인): 1~9호선, 경의중앙, 수인분당, 신분당, 공항철도, 경춘, 경강, 서해, 우이신설, 신림선. 인천 1·2호선, 김포골드라인, 에버라인, 의정부경전철은 API가 위치를 주지 않아 이 노선에서는 기능이 꺼진다.
- 실제 인증키로 **응답과 매칭까지 확인**했다(2호선 37대 중 선릉~사당 경로 위 6대 식별, 출발역에 선 열차 번호를 정확히 선택). 다만 **실제 탑승 중 동작은 지하철에서 확인해야 한다.** 붐벼서 다음 열차를 타면 다른 열차를 잡을 수 있다(경로를 벗어나면 다시 찾는다).
- **환승 경로**는 `JourneyPlanner`가 노선 그래프에서 시간이 가장 짧은 길을 찾는다(최대 2회, 급행 계통은 후보에서 제외). 경로 확인 화면에서 **빠른 길 / 환승 적게**를 고를 수 있다 — "환승 적게"는 환승 1회에 20분의 가상 비용을 매겨 경로를 고르고, 표시되는 소요시간에는 그 비용이 들어가지 않는다. 탑승 화면은 구간을 하나씩 따라가며, 환승역에 도착하면 "환승 열차 탔어요"로 다음 구간을 시작한다. 알림 문구도 환승용으로 바뀐다.
- **환승 시간은 서울교통공사 실측 도보 시간 + 대기 추정 120초**다. 실측은 1~9호선 환승역 71곳 196쌍(양방향)이고, 코레일 환승(부평 1↔인천1호선 등)처럼 데이터가 없는 곳은 도보 150초로 가정한다. 대기 120초는 배차 간격을 반영하지 않은 고정값이라 아직 추정치다.
- **급행 매칭**: 실시간 정보가 알려 준 탑승 열차가 급행이면 그 노선의 급행 계통으로 경로를 다시 짜고 다시 앵커링한다. 완행을 탔는데 급행 계통으로 잡혀 있으면 반대로 되돌린다.
- **재매칭**: 잡은 열차가 두 번 연속 응답에서 사라지거나 경로를 벗어나면 놓아주고, 출발역뿐 아니라 **현재 추정 역**에서도 다시 잡는다.
- 앱이 탑승 중에 강제 종료되면 **세션이 복원되지 않는다**. 예약된 알림은 그대로 울린다.
- 이어폰 오디오 알림, AlarmKit, 워치는 아직 없다 (기획서 8장 P0·P1).
